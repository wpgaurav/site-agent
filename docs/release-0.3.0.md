# Site Agent 0.3.0

Serves Bricks Builder's own abilities on Site Agent's endpoint and makes the bundled builder skills work on real sites. Access defaults are unchanged: everything starts disabled, and the new Bricks tools group is a separate opt-in.

Bricks 2.4 and later register about 165 abilities with the WordPress Abilities API when AI/MCP is enabled in Bricks > Settings > AI, and put a fast path of about a dozen on the official MCP Adapter's default server. With the Bricks tools group on, Site Agent serves that fast path under Bricks' own tool names, plus `bricks-start-here`, so Bricks' guidance applies unchanged. `site-agent-bricks-abilities` lists or describes the rest, and `site-agent-run-bricks-ability` runs them with the same `ability_name` and `parameters` Bricks passes to `mcp-adapter-execute-ability`; the server instructions say so. The group is available only while Bricks reports its abilities active, can be limited per Application Password, and is audited. Bricks keeps its master switch, per-ability deny-list, `manage_options` and builder permission checks and schemas, and its refusal reasons reach the client. `bricks/execute-php` is never a direct tool and also needs Site Agent's PHP execution group. A call that Bricks' own permission check refuses ends inside the adapter and is not audited.

The builder skills (Gutenberg, GenerateBlocks, Elementor, Bricks and Divi) are bundled, read with `list-skills` and `get-skill`, and backed by `builders` in `site-context` and `builder` in `get-content`. Content writes refuse Elementor, Bricks and Divi layout meta. Testing on gauravtiwari.org and anantamias.com found and fixed:

- Staged edits to live posts could not be read back: `get-content` now returns the autosave text with `autosave_content` and flags whether it is `newer`, so edits can be verified and chained.
- Staging an edit to a template failed with a REST "invalid template parent" error; it now returns `stage_unsupported` and asks for an explicit status.
- Bricks layouts without an editor mode, GenerateBlocks Pro blocks and GenerateBlocks global styles and conditions were misclassified.
- The Bricks read recipe failed on 7 of 61 Bricks pages on anantamias.com (up to 565 KB) because of the 64 KiB PHP limits. Bricks, Elementor and Divi recipes now read outlines or chunks and write element-level patches.
- Divi's lock check needed its admin include, Bricks CSS regeneration rebuilt every file on the site, code signatures were not mentioned, the companion described pre-0.2.0 staging and media behavior, and the HTTP smoke test hard-coded 16 tools.
